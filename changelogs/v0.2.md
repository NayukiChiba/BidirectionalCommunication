# BidirectionalCommunication v0.2

发布日期：2026-08-08

`v0.2` 完成分层内核和应用组合根，将消息领域规则、发送消息用例、技术适配器与
FastAPI 请求入口分离，并使用自动化架构测试保护依赖方向。

## 新增功能

### 消息领域模型

- 增加 `UserId`、`MessageId`、`ClientMessageId` 和 `MessageContent` 值对象。
- 增加 `ChatMessage` 领域实体，以服务端消息 ID 表达实体身份。
- 统一将消息创建时间规范化为 UTC。
- 在领域层维护用户标识、消息标识、非空正文和正文长度等不变量。
- Domain 保持为纯 Python，不依赖 FastAPI、Pydantic 或数据库框架。

### 发送消息应用用例

- 增加 `SendMessageService`，统一编排消息创建、保存和实时通知。
- 增加 `SendMessageCommand`、发送结果和投递结果模型。
- 定义最小 `MessageRepository` 和 `MessageNotifier` 端口。
- 明确保存失败、接收者离线、推送失败和非法消息等结果语义。
- 保持“先创建、再保存、后推送”的处理顺序。

### 技术适配器

- 增加内存消息 Repository，实现应用层消息存储端口。
- 增加 WebSocket 消息通知适配器，实现领域消息到传输事件的转换。
- 将 `ConnectionManager` 从程序入口提取到独立适配器。
- 保持重复登录替换、交错断开、发送失败清理和服务停止关闭行为。

### Entrypoint 与组合根

- 将 FastAPI 路由、Pydantic 协议模型和错误映射提取到 `entrypoints/`。
- 增加 `bootstrap.create_app()`，集中创建和注入具体依赖。
- 由 Bootstrap 统一管理 WebSocket 连接资源的关闭生命周期。
- `main.py` 收敛为唯一程序启动入口，只负责暴露 FastAPI `app`。
- 必要的组合对象通过 `app.state` 提供给生命周期和外部行为测试。

## 架构

依赖方向统一为：

```text
main → bootstrap → entrypoints / adapters → application → domain
```

- Domain 只依赖 Python 标准库和自身模块。
- Application 只依赖 Domain 和自身定义的端口。
- Adapters 实现 Application 所需的技术能力。
- Entrypoints 负责协议转换，不创建具体 Repository 或应用服务。
- Bootstrap 是唯一了解并组装所有具体实现的位置。

## 工程质量

- 增加 Domain、Application、Adapters 和 Bootstrap 分层测试。
- 增加洋葱架构导入检查，防止内层反向依赖外层。
- 验证具体 Repository、Notifier、Service 和连接管理器只在组合根创建。
- 保持健康检查、WebSocket 私聊、ACK 和稳定错误码等外部行为不变。
- 增加 VitePress 项目文档、消息模型文档和架构说明。
- 增加 GitHub Pages 文档自动部署工作流。
- Ruff 静态检查、格式检查和完整自动化测试均通过。


```bash

```

## 已知限制

- 消息仍然保存在单进程内存中，进程退出后会丢失。
- 在线连接只支持单进程，不支持多实例路由。
- 尚未实现登录认证，客户端仍可在连接时指定 `user_id`。
- 尚未实现历史消息、离线补发、消息幂等、送达确认和已读位置。
- 尚未引入 SQLAlchemy、数据库迁移和 Unit of Work。
- 不包含群聊、文件传输、语音、视频或完整客户端界面。
