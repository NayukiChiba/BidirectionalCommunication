# BidirectionalCommunication v0.1

发布日期：2026-08-04

`v0.1` 是项目的首个基础版本，实现了基于 FastAPI 和 WebSocket
的单进程双向文字通信能力。

## 新增功能

### WebSocket 通信

- 提供 `/ws?user_id=<用户ID>` WebSocket 接口。
- 支持在线用户之间实时发送和接收文字消息。
- 支持用户向自己发送消息。
- 服务端为消息生成唯一 ID 和发送时间。
- 消息投递成功后，向发送方返回 ACK 确认。
- 接收方离线时，向发送方返回结构化错误事件。

### 消息协议与校验

- 使用 Pydantic 校验客户端消息。
- 校验消息类型、接收方、消息内容和客户端消息 ID。
- 拒绝非法 JSON、空白消息、未知消息类型和多余字段。
- 禁止客户端伪造发送者 ID。
- 对协议错误返回稳定的结构化错误事件。

### 连接生命周期

- 使用内存连接表维护单进程在线用户。
- 每个用户只保留一个当前有效连接。
- 同一用户重复登录时，新连接替换旧连接。
- 被替换的旧连接以关闭码 `4001` 断开，原因固定为
  “该账号已在其他连接登录”。
- 旧连接退出时不会误删已经生效的新连接。
- 消息发送失败时自动清理失效连接。
- 应用停止时，以关闭码 `1001` 关闭当前连接并清空连接表。

### HTTP 接口

- 提供 `/health` 健康检查接口。

## 工程质量

- 覆盖健康检查、消息协议校验和错误响应。
- 覆盖定向消息、自发消息、离线消息和 ACK。
- 覆盖连接建立、断开、替换、发送失败和停机清理。
- 覆盖重复登录和新旧连接的不同退出顺序。
- 连接生命周期验收测试使用独立 `TestClient` fixture。
- 32 项自动化测试全部通过。
- Ruff 静态检查和格式检查通过。

## 快速启动

```bash
uv sync
uv run uvicorn main:app --reload
```

服务默认地址：

- HTTP：`http://127.0.0.1:8000`
- WebSocket：`ws://127.0.0.1:8000/ws?user_id=user-a`
- 健康检查：`http://127.0.0.1:8000/health`

## 已知限制

- 在线连接仅保存在单个进程的内存中。
- 不支持多进程、多实例或跨实例消息投递。
- 暂无登录认证，`user_id` 可以由客户端自行指定。
- 暂无数据库和消息持久化。
- 暂无离线消息、消息重试和可靠投递机制。
- 暂无已读回执。
- 进程退出后，所有在线状态都会丢失。
- 暂无应用级心跳和空闲连接超时机制。
- 暂不包含完整客户端界面。
