# BidirectionalCommunication v0.3

发布日期：2026-09-03

`v0.3` 完成 M4 持久化聊天里程碑，在保持 Domain 和 Application 不依赖数据库框架
的前提下，引入 SQLite、SQLAlchemy、Repository、Unit of Work、Alembic、历史分页、
离线恢复、消息幂等和异步数据库访问。

## 新增功能

### SQLite 消息持久化

- 增加 `MessageRecord` SQLAlchemy 2.x ORM 映射。
- 默认将消息持久化到 `data/chat.sqlite3`。
- 数据库路径统一通过 `src/config.py` 和 `pathlib` 管理。
- 显式分离 `ChatMessage` 领域实体与 ORM 持久化记录。
- 增加领域消息与 ORM 记录之间的双向转换。
- 使用主键、检查约束和联合唯一约束保护消息数据。

### Repository 与 Unit of Work

- 扩展最小 `MessageRepository` 端口，支持消息保存、幂等键查询和单聊历史查询。
- 增加 `MessageUnitOfWork` 和每用例独立 UoW 工厂端口。
- Repository 不提交事务，由 UoW 统一负责提交、回滚和资源释放。
- 提供内存与 SQLAlchemy 两种实现，并使用共同契约测试验证关键行为。
- 发送消息保持“事务提交成功后再实时推送”的可恢复顺序。
- 保存或提交失败时不执行实时推送。

### Alembic 数据库迁移

- 初始化 Alembic 迁移环境并纳入版本控制。
- 增加首个消息表迁移 `e5f06ff274b9`。
- 增加单聊历史复合索引迁移 `b5db92390df6`。
- 应用启动不再调用 `metadata.create_all()` 或自动升级数据库。
- 新环境启动前必须显式执行 `alembic upgrade head`。
- 支持空库升级、降级到 `base`、重新升级和 ORM 元数据一致性检查。
- 测试和学习实验使用独立 SQLite 文件，不污染开发数据库。

### 历史消息与离线恢复

- 新增单聊历史 HTTP 接口：

  ```http
  GET /messages/history?user_id=user-a&peer_id=user-b&limit=50
  ```

- 使用 `(created_at, message_id)` 正向排他游标分页。
- 默认每页 50 条，最多 100 条。
- 相同创建时间的消息通过唯一服务端消息 ID 稳定排序。
- `next_cursor` 可以保存为客户端的最后同步位置。
- 接收者离线或实时推送失败时，已提交消息仍保存在数据库。
- 客户端重连后可以携带旧游标主动拉取缺失消息。
- 本版本不建立额外离线队列，也不自动推送历史消息。

### 消息幂等

- 使用 `(sender_id, client_message_id)` 作为消息幂等键。
- 重复提交相同客户端消息 ID 时返回原消息及相同 `server_message_id`。
- 数据库唯一约束保证并发重复插入只接受一条记录。
- 应用在唯一约束竞态后使用新 UoW 读取已经胜出的原消息。
- 重试可能再次触发相同消息的 WebSocket 推送，客户端可按服务端消息 ID 去重。

### 异步数据库访问

- 引入 `aiosqlite` 和 SQLAlchemy asyncio 扩展。
- 应用运行时使用 `AsyncEngine`、`AsyncSession` 和 `async_sessionmaker`。
- Repository、Unit of Work、发送消息和历史查询全部使用异步接口。
- 每个并发 Task 创建并持有独立 AsyncSession。
- 应用关闭时显式执行 `await engine.dispose()`。
- 设置 `expire_on_commit=False`，避免提交后属性访问隐式触发 I/O。
- 消息 ORM 不包含懒加载 relationship 或 deferred 字段。
- Alembic 运维命令继续使用独立同步连接，不进入应用运行时请求链路。

## 数据库结构

消息表包含：

```text
messages
├── message_id         VARCHAR(36)  PRIMARY KEY
├── client_message_id  VARCHAR(36)  NOT NULL
├── sender_id          TEXT         NOT NULL
├── recipient_id       TEXT         NOT NULL
├── content            TEXT         NOT NULL
└── created_at         DATETIME     NOT NULL

UNIQUE (sender_id, client_message_id)
INDEX  (sender_id, recipient_id, created_at, message_id)
```

SQLite 查询计划测试确认双向单聊查询的两个分支能够复用历史查询复合索引，不需要维护
反向重复索引。

```bash
uv run uvicorn main:app --reload
```

```bash

uv run ruff check .
uv run alembic check
uv run pytest
```

## 已知限制

- 尚未实现身份认证，WebSocket 和历史接口中的用户 ID 仍由客户端提供。
- 在线连接仍只保存在单进程内存中，不支持多实例路由。
- 离线恢复需要客户端主动调用历史接口，不会在重连后自动推送。
- WebSocket 实时事件不承诺恰好一次，客户端需要按 `server_message_id` 去重。
- 尚未实现送达状态、已读位置和断线自动补偿流程。
- aiosqlite 不改变 SQLite 同时只有一个写入事务的限制。
- 当前未启用 WAL，也未迁移到 PostgreSQL。
- 不包含群聊、文件传输、语音、视频或完整客户端界面。
