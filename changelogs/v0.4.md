# BidirectionalCommunication v0.4

发布日期：2026-09-05

`v0.4` 完成 M5 可信私聊里程碑。在 v0.3 持久化消息能力之上，加入用户认证、稳定的
一对一会话身份、成员权限、累计送达与已读位置，以及可重复执行的 WebSocket 重连
补偿流程。

## 新增功能

### 用户注册与认证

- 增加用户注册、登录和当前用户 HTTP 接口。
- 使用 Argon2id 保存带随机盐的密码哈希，数据库不保存明文密码。
- 使用短期 Bearer JWT 为 HTTP 和 WebSocket 建立统一可信身份。
- JWT 明确验证签名、算法、`sub`、`iat` 和 `exp`，并查询数据库确认用户仍然存在。
- WebSocket 在接受和登记连接前完成认证，不信任 URL 或消息载荷中的发送者身份。
- 用户名规范化后由数据库唯一约束保护，并发注册不能创建重复账号。

### 一对一会话与成员权限

- 增加 `Conversation` 聚合根和稳定 `ConversationId`。
- 一对一会话固定包含两名不同且已经注册的用户。
- 增加 `conversations` 和 `conversation_members` 表及 ORM 映射。
- 使用顺序无关的成员组合唯一键，保证同一对用户只有一个会话。
- 实现创建或获取会话接口：

  ```http
  POST /conversations
  Authorization: Bearer <JWT>
  ```

- 发送消息和读取历史前均验证当前用户属于目标会话。
- 会话不存在和非成员访问使用相同外部错误，避免泄露会话是否存在。
- 历史查询迁移到稳定会话身份：

  ```http
  GET /conversations/<conversation_id>/messages
  Authorization: Bearer <JWT>
  ```

- 消息历史索引更新为
  `(conversation_id, created_at, message_id)`，继续支持稳定游标分页。

### 保存、推送、送达和已读语义

- 明确区分四个阶段：
  - `accepted`：消息已经校验并提交到数据库。
  - `pushed`：服务端完成一次 WebSocket 写入，仅作为实时推送观测。
  - `delivered`：客户端明确确认已经处理至某个累计位置。
  - `read`：客户端明确确认用户已经阅读至某个累计位置。
- 发送方成功响应由旧 ACK 调整为 `accepted`，不再把网络写入误称为送达。
- `accepted` 通过 `push_status` 区分 `pushed`、`recipient_offline` 和 `failed`。
- 接收者离线或推送失败不会回滚已提交消息。
- 已读位置必须由对应的认证成员提交，载荷不能指定或伪造其他成员身份。

### 累计位置与重连补偿

- 使用 `(created_at, message_id)` 作为可单调推进的稳定消息位置。
- 为每名会话成员持久化累计 `delivered` 和 `read` 位置。
- 使用原子条件更新保证重复、倒序和并发确认都不能使位置后退。
- 已读位置不能超过当前已送达位置。
- 确认消息必须真实存在并属于目标会话。
- 新增累计确认命令：

  ```json
  {
    "type": "acknowledge_position",
    "conversation_id": "<conversation UUID>",
    "position_type": "delivered",
    "message_id": "<server message UUID>"
  }
  ```

- 新增 WebSocket 重连同步命令 `sync_messages`，客户端提交最后连续保存的消息 ID，
  服务端返回该位置之后的缺失消息。
- 重复确认和重复同步保持幂等；网络仍采用至少一次语义，客户端按
  `server_message_id` 幂等保存和去重。

## 数据库迁移

本版本新增三个 Alembic revision：

- `f53ad4a832a9`：创建认证用户表。
- `c18a4f7d2e91`：创建会话和成员表，为旧消息回填会话身份并更新历史索引。
- `d19b6c8e4f02`：增加成员累计送达与已读位置、消息外键和成对可空检查约束。

升级已有数据库：

```bash
uv run alembic upgrade head
```

会话迁移不会静默接纳不满足新规则的旧数据。旧消息若包含自发消息或引用未注册用户，
迁移会明确停止，需要先检查和处理这些历史测试数据。

## 工程与文档

- Domain 继续保持纯 Python，不依赖 FastAPI、Pydantic 或 SQLAlchemy。
- Application 通过会话、消息、认证和累计位置端口表达用例。
- SQLite 运行时显式启用外键约束。
- 增加认证、会话聚合、成员权限、并发创建、累计位置和断线窗口测试。
- 验证并发会话创建不会生成重复记录。
- 验证并发位置更新即使乱序提交也不会倒退。
- 自动化测试增加到 177 项。
- Ruff 格式与静态检查通过。
- Alembic head 与 ORM 元数据一致性检查通过。
- VitePress 文档构建通过，并增加客户端重连集成顺序说明。

## 已知限制

- 在线连接仍保存在单进程内存中，不支持多实例消息路由。
- 同一用户当前只保留一个有效 WebSocket 连接。
- 送达和已读位置按用户累计保存，尚不区分手机、桌面等多个设备。
- 网络层不承诺恰好一次；客户端必须按 `server_message_id` 幂等保存和去重。
- 访问令牌暂不支持刷新和主动吊销。
- 当前没有好友关系和用户搜索，会话创建需要已知对方用户 ID。
- SQLite 仍然只有一个并发写入者，当前没有启用 WAL，也尚未迁移到 PostgreSQL。
- 不包含群聊、文件传输、语音、视频或完整客户端界面。
